{% comment %} The tab strip above a mutation table: Filter, Samples, Rows, Display, in that order, and a page passes only the ones it has content for. **`single_sample` changes two things at once, and they are one fact.** Where the picker chooses exactly one sample -- the per-sample Mutations page, whose whole subject is that sample -- the tab is called **Sample** and comes first. Plural would promise a multi-select the pane does not offer, and the tab that decides what the rest of the page is *about* belongs before the tabs that adjust how it is shown. Everywhere else the menu is a multi-select and the strip reads as it always has. The same shape as the Import data page's strip (import/_tabs.html) and the curate toolbar, but client-side: Bootstrap's tab plugin -- inside the DataTables bundle at the end of body, never bootstrap.min.js on its own -- switches the panes, and js/mutint_control_tabs.js restores and remembers the tab as `.tab` through the preference store. Every pane must sit in one `.tab-content`, because the plugin deactivates only the target's siblings. Takes `page` (the pane ids' prefix and the preference key's), `active`, and `prefs_id`, `authenticated`, `preferences_url` spelled out -- an include from inside an inclusion tag has no `request` to read them from. {% endcomment %}

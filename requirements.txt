# GenomeDiff (.gd) parser/writer used by the drag-and-drop mutation import.
# Pinned to a git SHA, not a PyPI version: only 0.4.1 was ever published there, and
# what this depends on landed after it -- the INT mutation type, the ordered
# Record.__str__ serializer gd_import.py and Mutation.to_gd_line() rely on, and now
# breseq's SC/MP/DP/PD/MASK entry types plus tolerance of ones it has not seen.
# Without that last part a current breseq output.gd fails to load in full.
#
# 43a0f72 adds genomediff.schema -- breseq's own field guards, mirrored from
# genome_diff_entry.cpp -- behind Record.get()/set()/validate(). mutint_curate
# checks hand-entered mutations against it rather than keeping a second opinion about
# what breseq accepts. It also stops a malformed line costing the whole file: problems
# collect in gd.parse_errors, which the import summary now reports per file.
#
# b607759 makes the `#=` header multi-valued: a name may legitimately appear more than once --
# breseq writes one READSEQ per read file and one REFSEQ per reference file -- and `read` used
# to keep only the last of them while `write` emitted only one line per name. `metadata.getlist`
# is what `gd_import.read_files_named_by` asks for, and is how a sample records the reads it was
# made from. The scalar view is unchanged, so nothing else here moved.
#
# The SHA is the whole pin, and it is the *full* one: the commit is the exact identity of this
# dependency, and an abbreviation is a prefix rather than an identity. `direct_url.json` records
# the full hash either way. Versions did not move between commits until b607759 released 0.4.3,
# which is why --force-reinstall below exists and why it is still the safe way to move.
#
# **Pinning does not make pip act on a change, and no flag here does.** Measured against this
# venv with a different SHA: `pip install -r requirements.txt` plans **zero** installs, and so
# does `--upgrade` -- pip clones the new revision, builds its metadata, sees 0.4.2 already
# installed and calls the requirement satisfied, ignoring the recorded revision. The entry
# script's venv fingerprint does notice the edit and re-runs pip; pip is what declines. So an
# existing environment needs
#   pip install --force-reinstall --no-deps 'git+https://github.com/barricklab/genomediff-python.git@<sha>'
# (dev: `pip install -e /path/to/genomediff`)
#
# This is the same class of problem as breseq-prerelease in mutint-breseq/tools.txt, where
# every build also reports one version -- and there it *is* fixable, because conda publishes
# the git hash as the build string and a spec can pin that. pip has no equivalent: a direct
# URL carries no version for a requirement to match on.
genomediff @ git+https://github.com/barricklab/genomediff-python.git@b60775963f3f79ef24a321dd659020dce60442b5

# Reads the stored BAM in mutint_import/coverage.py, to weight each alignment by 1/X1 --
# breseq's redundancy tag, the number of places a read mapped equally well. Without that
# weighting a read matching ten IS copies is counted once at each and repeats dominate the
# coverage track.
#
# The reason it is a dependency rather than a hand-rolled reader: htslib stores an integer
# aux tag in the SMALLEST type that fits, so breseq's `X1:i:<n>` is not type `i` in the
# file. Measured on a stored BAM, bowtie2's own `AS:i:` is stored as `C` (and `c` when
# negative), never `i`. A reader matching one type would silently find no tags, weight every
# read 1, and report success. read.get_tag() is htslib's own decode and has no such edge.
#
# It also writes BAMs, which is what makes the tagged test fixtures possible: there is no
# samtools in env/tools, so before this there was no way to produce one.
pysam>=0.24
